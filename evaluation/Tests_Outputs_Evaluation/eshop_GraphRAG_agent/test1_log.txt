FEEDBACK:
The implementation incorrectly handles product updates.

When a product already exists, the system currently overwrites its stock values instead of increasing them. This leads to loss of previously added stock and breaks consistency, especially when updates happen multiple times or when there are active reservations.

Required behavior:

When adding an existing product:
total_stock must be increased by the new value (not replaced)
available_stock must be increased by the same amount
Existing reservations must remain unchanged
Available stock must always reflect the current state after reservations

This issue causes incorrect results in scenarios with:

repeated product additions
price updates combined with stock updates
updates while items are already reserved
checkout after product updates

Fix the product update logic so that stock is accumulated instead of overwritten, while preserving reservation consistency.
